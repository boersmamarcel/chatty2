## Why

The agent's shell output and the embedded terminal both read the screen through `snapshot()`. The doc comments on `Region` and `TerminalText` promise more than the two existing tests check. A regression in any of these would garble what the agent reads.

## Repo and files

* `crates/chatty-terminal/src/snapshot.rs` — add tests in its `#[cfg(test)] mod tests`.
* Only this file changes. If a test shows the code does not do what the doc says, the smallest fix in this same file is allowed. Say so in the PR. Do not change the public API.

## Change

Add tests built with `alacritty_terminal::term::test::mock_term`, as the existing `soft_wrapped_rows_join_and_blank_rows_trim` is:

1. **Per-line trim:** a screen whose lines end in spaces (`"ab   \r\ncd  "`) gives `"ab\ncd"`.
2. **Wide characters appear once:** a line with a double-width character (`"漢x"`) gives that text exactly once, with no extra spacer cell.
3. **Scrollback row limit:** with more content rows than requested, `Region::Scrollback { lines: 2 }` returns only the last 2 content rows.
4. **`lines: 0` counts as 1:** `Region::Scrollback { lines: 0 }` returns exactly the last content row.

## Mutation check

* Test 1 (per-line trim) and test 2 (wide characters): **None in `snapshot.rs`.** Both
  behaviours come from alacritty's `Term::bounds_to_string`, which `snapshot()` calls; the tests
  pin that upstream contract. State that instead of inventing a line to break.
* Test 3 (row limit): changing the Scrollback limit from `lines` to `lines + 1` fails it.
* Test 4 (`lines: 0`): removing the `lines.max(1)` clamp fails it.
