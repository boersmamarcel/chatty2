## Why

`TerminalConfig.env` promises: "`TERM=xterm-256color` and `COLORTERM=truecolor` are set unless given here" (`lib.rs` around line 616). Programs in the agent's shell pick colours and line editing from these. No test checks either the defaults or that a caller's own value wins.

## Repo and files

* `crates/chatty-terminal/tests/headless.rs` — add tests.
* Only this file changes. No behaviour change.

## Change

In `tests/headless.rs`, using the existing `sh(script)` helper and `wait_until` or `screen_contains`:

1. **Defaults:** a terminal from `sh("printf '[%s|%s]' \"$TERM\" \"$COLORTERM\"")` shows `[xterm-256color|truecolor]` on screen.
2. **A caller's TERM wins:** with `env` containing `TERM=dumb` (and no `COLORTERM`), the screen shows `[dumb|truecolor]`.
3. **A caller's COLORTERM wins:** with `env` containing `COLORTERM=24bit`, the screen shows `[xterm-256color|24bit]`.
